## Workflow doc reorientation (the next big task — WAIT for incoming notes)

**Problem (my understanding):** the current fitting-workflow documentation is
too **IF2-centric** and organized around the **staged-fit** mechanics. That
framing teaches the pipeline plumbing rather than the actual task — how to fit a
model and know whether the fit is any good.

**Desired reorientation:** a general "how to fit" guide that orients the reader
to the _task_, not one algorithm's stages:

- The menu of fitting subcommands and when to reach for each (`fit run`,
  `pfilter`, `profile`, `survey`) — what question each answers.
- Generating **synthetic data** to validate recovery before trusting a real fit
  (simulate from known params → fit → did you get them back?).
- Reading **particle-filter health**: ESS and the `--pf-health` (ESS / τ²)
  diagnostic; recognizing **particle degeneracy** (the filter collapsing to a
  few distinct ancestors).
- Diagnosing **failing fits**: stuck chains, poor mixing, low ESS — what to look
  at and what each symptom usually means.
- The **PGAS-specific failure mode** (the one worth spelling out): PGAS
  alternates a conditional SMC (CSMC) that resamples the latent trajectory given
  a reference path, and a parameter update conditioned on that trajectory. When
  the particle filter degenerates, the conditional sampler **collapses back onto
  the reference path** — the latent trajectory isn't actually
  refreshed/explored, so the parameter moves (conditioned on a non-mixing latent
  state) stall. Symptom: the chain looks stuck / parameters barely move / high
  autocorrelation, and the root cause is _the conditioned sampler isn't
  exploring the latent space_, not the parameter proposal per se. Mitigations to
  mention: more particles, check the model isn't near-deterministic (degenerate
  observation density), reparameterize, check ancestor sampling is actually
  refreshing the path.

**Do not draft this verbatim from the dictation** — the above is the _intent_,
to be written cleanly once the incoming agent notes on recent fitting workflows
arrive. Identify the actual file first (likely the `camdl docs workflow` topic
source under `docs/`; confirm the path).
